# CorporateLuxe property enquiry

The public root and `corporateluxe.html` present CorporateLuxe in partnership with AirLandlords. They reuse the existing black/gold landing design and lead receiver, now with a three-step enquiry inspired by the supplied reference flow.

1. Full UK postcode, bedrooms (studio to 10), email.
2. Letting duration, whole property/private room, preferred start.
3. Full name, mobile and enquiry-only consent.
4. Confirmed private Sheet write, then personal-review confirmation and call/viewing contact options.

There are no public rent, uplift or condition-percentage controls. No automatic market valuation is generated: there is no approved postcode/bedroom income dataset. Blank estimate cells mean no figure has been calculated, and `Estimate Status` is `Personal review requested`. Add a licensed/approved data source before promising an instant income range. Do not reuse a competitor's displayed figure as market data.

`enquiry.js` keeps contact details in memory, validates each step, preserves answers on Back, normalizes postcodes and waits for a matching request receipt before displaying success. It does not send email or subscribe anyone to marketing. A request ID prevents duplicate writes on retry. `enquiry.css` styles the wizard; `landing.css` and the existing illustrative photo remain shared. `admin.html` retains the original internal calculator and PIN 1234; this static PIN is a convenience, not secure authentication.

## Storage

`Code.gs` is deployed as version 5 of the existing web-app endpoint in `config.js`, executing as the existing AirLandlords owner with the previously granted Sheets scope. It preserves the old payload handler and server calculation for compatibility, and accepts the new `corporateluxe-v2` payload. The private Sheet remains private. No read endpoint exposes lead data.

Existing columns A:T and all previous leads remain intact. Column F now stores bedroom count for V2. U:AA add Full Name, Letting Duration, Property Scope, Start Time, Estimate Status, Brand and Flow Version. Source is `Property Earnings Calculator`, status `New Lead`, and the timestamp is generated by the receiver. V2 estimate columns G:J remain blank. Formula prefixes are escaped. Consent, fields and enum values are checked on the server; a lock and field-bound request ID guard retries. Origin/honeypot checks are only lightweight abuse deterrents, not authentication.

Synthetic test enquiries are labelled `Test - do not contact` after readback. Do not follow them up.

## Validation

Run `node verify.mjs`: retained legacy server calculation/receipt, retries, conflicts, malformed submissions, enquiry consent, formula escaping, plus new qualified-enquiry storage, added columns, blank estimate fields, allowed origins and failure handling. Browser QA covers property → plans → contact → confirmed write, mobile layout and saved Sheet field readback. Tests use synthetic `calculator-test@example.com` / `07700 900123` contacts.

No social posts, marketing emails or ads are sent automatically. Campaign artwork uses an AI-generated illustrative interior, not a claimed managed property. Prepared captions describe a personal review rather than an instant calculation.
